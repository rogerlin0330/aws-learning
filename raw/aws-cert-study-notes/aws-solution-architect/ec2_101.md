## 1. What Is EC2?

**Elastic Compute Cloud (EC2)** is AWS's default and most essential compute service. It provides virtual machines called **instances** and should be the starting point for almost any compute requirement in AWS.

- **Service Type:** Infrastructure as a Service (**IaaS**)
- **Unit of consumption:** the **instance** (an OS configured with allocated resources)
- **Use it when you need:** an operating system, runtime environment, database dependencies, applications, or application interfaces that you want to manage yourself

---

## 2. Core Architectural Characteristics

### Private by Default

EC2 is a **private AWS service** — it runs in the private AWS zone by default.

- An instance is launched into **one specific VPC subnet**
- Public access must be **explicitly configured**
    - The default VPC handles this configuration automatically
    - Custom VPCs require manual configuration (covered later)

### AZ Resilient (Not AZ Fault-Tolerant)

Because an instance lives in a subnet, and a subnet lives in a single **Availability Zone**:

> ⚠️ **If the AZ fails, the instance fails.**

Remember this — it's a recurring exam concept.

### Customizable Sizing & Capabilities

When launching, you choose:

- CPU and memory size
- Optional GPUs
- Advanced storage and networking
- Special-purpose processors

Some of these can be changed **after launch**.

### Shared Responsibility (IaaS Model)

|You Manage|AWS Manages|
|---|---|
|Operating System|Virtualization|
|Runtime, apps, data|Physical hardware|
|OS-level configuration|Networking infrastructure|
||Storage infrastructure|
||Facilities|

## 3. Billing Model

EC2 uses **on-demand billing** — pay only for what you consume.

- Billed **per second** or **per hour** (depends on the software running)
- Billing components:
    1. **Compute charge** — CPU + memory
    2. **Storage charge** — disks attached to the instance
    3. **Extras** — commercial software licensing (if applicable)

### Storage Options

- **Local host storage** — on the physical EC2 host
- **Elastic Block Store (EBS)** — network-attached block storage (separate AWS service)

## 4. Instance Lifecycle & States

Focus on these three states:

```
   ┌──────────┐    Stop      ┌──────────┐   Terminate    ┌────────────┐
   │ RUNNING  │ ────────────►│ STOPPED  │ ──────────────►│ TERMINATED │
   │          │◄──────────── │          │                │ (one-way!) │
   └──────────┘    Start     └──────────┘                └────────────┘
```

> 💡 See **Section 2 of the infographic above** ("Instance Lifecycle & Costs") for a clean visual of these transitions — note especially that **Stop ↔ Start** is bidirectional, but **Terminate** is a one-way arrow.

(Intermediate states like _pending_, _stopping_, _shutting-down_ exist, but the big three matter most.)

### State-by-State Costs

|Component|Running|Stopped|Terminated|
|---|:-:|:-:|:-:|
|**CPU**|💰 Charged|✅ Free|✅ Free|
|**Memory**|💰 Charged|✅ Free|✅ Free|
|**Networking**|💰 Charged|✅ Free|✅ Free|
|**Storage (EBS)**|💰 Charged|💰 **Still Charged!**|✅ Free (deleted)|

> 🔑 **KEY EXAM POINT:** A **stopped** instance still incurs **storage charges**. The disks remain allocated. The only way to eliminate all costs is to **terminate** the instance.

> ⚠️ **Termination is permanent and non-reversible.** Storage is deleted along with the instance.

## 5. AMI — Amazon Machine Image

An **AMI** is an _image_ of an EC2 instance. Think of it like:

- A server image (on-prem virtualization)
- A USB installer for Windows/macOS/Linux

### Two-Way Relationship

- An **AMI can be used to create** an EC2 instance
- An **EC2 instance can be used to create** an AMI

### What an AMI Contains

**1. Permissions** — controls who can launch from it:

|Permission|Who Can Use It|
|---|---|
|**Public**|Everyone (e.g., AWS-provided Linux/Windows images)|
|**Owner**|Only the AMI owner (implicit)|
|**Explicit**|Specific AWS accounts the owner grants access to|

**2. Boot Volume**

- Contains the C: drive (Windows) or root volume (Linux)
- Can also include additional data volumes
- Always has **at least one** volume — the boot volume

**3. Block Device Mapping**

- Configuration that **links volumes to device IDs** the OS expects
- Determines which volume is the boot volume vs. data volumes
- Tells the OS "this volume = /dev/sda1", etc.

## 6. Connecting to EC2 Instances

|OS|Protocol|Port|Authentication|
|---|---|:-:|---|
|**Linux**|SSH|**22**|SSH key pair (direct authentication)|
|**Windows**|RDP|**3389**|SSH key pair → decrypt admin password → RDP login|

### SSH Key Pair Mechanics

When you create a key pair, two parts are generated:

- **Private key** — _you_ download this **once and only once**. Keep it safe!
- **Public key** — AWS keeps this and places it on any instance you select that key pair for

### How Authentication Works

- **Linux:** The private key directly authenticates you to the instance (matches the public key on the instance)
- **Windows:** The private key is used to **decrypt the local Administrator password**, which you then use to connect via RDP

## 7. Key Takeaways (Exam-Ready Summary)

1. **EC2 = IaaS** — you manage OS and above; AWS manages everything below
2. **EC2 is the default compute service** in AWS
3. **Private by default** — explicit configuration needed for public access
4. **AZ resilient, not AZ fault-tolerant** — instance dies if its AZ fails
5. **Three key states:** Running, Stopped, Terminated
6. **Stopped ≠ Free** — you still pay for attached storage (EBS)
7. **Terminated = Permanent** — frees all costs but deletes data forever
8. **AMI** = template for instances; carries permissions, volumes, and block device mapping
9. **SSH port 22** (Linux), **RDP port 3389** (Windows)
10. **Private key is downloaded once** — losing it means losing access

## 8. Quick-Reference Cheat Sheet

|Concept|Detail|
|---|---|
|Service category|IaaS — Infrastructure as a Service|
|Resilience model|AZ resilient (single-AZ failure = instance failure)|
|Default network posture|Private (within a VPC subnet)|
|Billing granularity|Per second or per hour|
|Free state|Only **Terminated** (storage is deleted)|
|Hidden cost trap|**Stopped** instances still pay for EBS storage|
|Template object|AMI (Amazon Machine Image)|
|Linux access|SSH on port 22 + private key|
|Windows access|RDP on port 3389 + private key (to get admin password)|
|Key download policy|Private key downloadable **once** only|
