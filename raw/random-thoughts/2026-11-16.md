## EventBridge

It is a serverless service for building event-driven applications.

### Event Bus (Default & Custom)

#### How events flood into event buses

Custom apps: use AWS EventBridge SDK PutEvent
AWS Services: supported by default
Partner event sources: able if supported

#### Rules that match on event data

You specify what EventBridge does with the events delivered to each event bus (e.g. default/custom).

### Scheduler

#### Rules that run on a schedule

You can also create rules that sends events to the specified targets at specified intervals. For example, to periodically run an Lambda function, you can create a rule to run on a schedule.

### Quick Note

Cross-Account IAM Role Permission Configuration (Top Right of the Screen):

- Location: This XStackOutRole must be created in the target account that owns the source stack (SharedVPCStack) (e.g., account 1234...).
- Permission Policy: The role must have the cloudformation:DescribeStacks permission in order to read the Outputs of SharedVPCStack.
- Trust Policy: The role must trust and allow the current account initiating the deployment (or the CloudFormation service / Lambda execution role performing the deployment) to perform sts:AssumeRole on it.

When Do You Need iam:PassRole

- Allow someone to pass a role to CloudFormation for resource creation/update/delete, so that he/she can have the ability to manage resources via CloudFormation without the need to being attached those permissions directly.
- Allow CloudFormation stack role or the stack admin user to pass a role to services like Lambda as the execution role.
