# NACL vs Security Group

I think that NACL is on the network layer (Layer 3), while Security Group is on the application layer (Layer 7).

Actually, when debugging resource reachability, the order is check network layer first, e.g., VPC, subnet, NACL, VPC peering connection, etc, then application layer (Security Group, protocols, ports, etc).

Also, when talking about SG, one should understand what kind of AWS resources/services have the SG concept. For example, my thought right now is that usually if a resource has a server/instance concept (e.g. EC2, RDS instance, MSK instance, application load balancer,etc), then it usually has a SG concept. However, if a service doesn't have a server/instance concept (e.g. S3, Lambda, serverless node$, etc), then it usually doesn't have a SG concept.
