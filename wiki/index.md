## Services

- [IAM](services/iam.md) — Identity & access management; users, roles (trust + permissions policies, STS), policies (JSON syntax & case sensitivity), ARNs, federation
- [VPC](services/vpc.md) — Virtual network; default vs custom VPC (1 default per region max; default has fixed scheme, custom is flexible; default can be deleted and recreated; some services behave oddly without one), valid CIDR sizes `/16`–`/28` (VPC and subnet), 5 reserved IPs per subnet, route table cardinality (1 subnet has 1 route table; 1 route table can attach many subnets), main vs custom route tables (every VPC has 1 auto-created main route table with the local route; fallback for unassociated subnets; cannot be deleted directly — promote a custom table to main first; best practice: leave main untouched, explicitly associate every subnet with a custom table), subnets, routing, IGW, NACL, SG, NAT GW, PrivateLink
- [EBS](services/ebs.md) — Elastic Block Store; volume types (GP2 credit-bucket vs GP3 flat-rate, IO1/IO2/Block Express provisioned IOPS, ST1 throughput-optimized HDD, SC1 cold HDD), two-ceiling rule (per-volume vs per-instance), IOPS/GB ratio caps, 1 MB HDD I/O block, Elastic Volumes migration, EBS vs instance store decision framework (RAID 0 per-instance ceiling ~260K IOPS; beyond that → instance store), encryption (envelope encryption on KMS; `GenerateDataKeyWithoutPlaintext` + AES-256 at the hypervisor; DEK reuse chain through snapshots and restored volumes; account-level default encryption; irreversible)
- [EC2](services/ec2.md) — Virtual compute; IaaS foundations (instance = OS + allocated resources, private-by-default in a VPC subnet, AZ-resilient not fault-tolerant, customizable at launch, shared responsibility line at the hypervisor), hosts vs instances (host = physical AWS-managed hardware in one AZ; instance = VM AZ-bound through its host; everything — host, subnet, ENI, EBS, instance store — is AZ-scoped; cross-AZ relocation requires snapshot/AMI), tenancy options (Shared default / Dedicated Instance / Dedicated Host with per-host billing and BYOL per-socket licensing), billing model (per-second/per-hour compute + always-on storage + commercial-license extras), instance lifecycle state machine (Running ↔ Stopped → Terminated; intermediate states; stop ≠ free because EBS keeps billing; terminate is one-way and deletes the root volume by default), stop/start vs restart (restart keeps the same host so instance-store and auto-public-IP survive; stop/start may land on a new host in the same AZ so both are lost), status checks and auto recovery (two checks — System for the host/service and Instance for the OS, healthy = 2/2; CloudWatch Status Check Alarm fires on either failing for ≥ 1 consecutive 5-minute period and can notify SNS + optionally Reboot/Stop/Terminate/Recover; auto recovery = same-AZ heal that preserves **all** IP addressing including the auto public IPv4 and EIP; EBS-only, supported instance type, spare host capacity required; **not** cross-AZ — not a substitute for multi-AZ HA; Simplified Automatic Recovery is the modern default for most current-generation types), storage options (instance store ephemeral on the host vs EBS network-attached persistent), instance store (physically local to host; highest AWS performance; D3 ~4.6 GB/s HDD / i3 ~16 GB/s NVMe ~2M IOPS; launch-time only; reboot preserves / stop-start destroys; included in instance price), network interfaces (ENI is the unit of network identity, not the instance — IPs/DNS/MAC/EIP/IPv6/SGs/src-dst check all per-ENI; 1 primary non-detachable + 0+ secondary detachable-movable; all ENIs same AZ but can span subnets; private DNS `ip-X-X-X-X.ec2.internal` VPC-only; public DNS `ec2-X-X-X-X.compute-1.amazonaws.com` with **split-horizon** behaviour — private IP inside VPC, public IP outside; auto public IPv4 dynamic and OS-invisible, IPv6 OS-visible; EIP attach replaces dynamic public IP, detach gives a new different one; movable secondary ENI pattern for MAC-licensing and IP failover; source/dest check must be off for NAT instances), Instance Metadata Service (link-local `http://169.254.169.254/latest/meta-data/` on every instance; only way for code on the instance to discover its own **public IPv4**; how SDKs fetch **IAM role temporary credentials** without baked-in keys; also user data + EC2 Instance Connect SSH keys; IMDSv1 unauthenticated + plain HTTP — SSRF-exploitable, Capital One 2019 pattern; enforce **IMDSv2** session-token handshake via `HttpTokens=required`), AMI as launch template (a **logical container** holding AMI ID + permissions + block device mapping pointing at EBS snapshots — no volume data in the AMI itself; sources = AWS / Community / Marketplace with Marketplace adding a per-hour license charge on top of the instance rate; permission modes **Private** default / Public / Explicit named accounts; four-phase lifecycle Launch → Configure → Create Image → Launch; region-specific but deployable to **any AZ in the region**; **cannot be edited** — launch, modify, recreate; can be copied across regions with `copy-image`, permissions reset to Private; billed on **EBS snapshot used data**, not the container or the volume's allocated size; **AMI baking** = configure once, capture, stamp out many), connecting to instances (Linux SSH/22 direct public-key auth; Windows RDP/3389 with private key used to decrypt the local Administrator password first), SSH key-pair mechanics (private key downloads once, AWS keeps the public key), when to use EC2 (default compute; long-running 24/7, OS-specific workloads, monolithic stacks, on-prem VM migrations, traditional DR — deviate to Lambda/Fargate/Beanstalk only when a specific requirement justifies it), instance types (5 categories: General Purpose / Compute Optimized / Memory Optimized / Accelerated Computing / Storage Optimized; type name decode: family+generation+capability-letters+size; burstable T3 vs steady-state M5; Graviton ARM families A1/M6g), bootstrapping (self-configure at launch via **user data** served over IMDS at `/latest/user-data/`; runs **once** as root, **opaque** to EC2 so a failed bootstrap still passes status checks = silent bad config; not a secret store — no long-term creds; 16 KB cap; console auto-base64s but CloudFormation needs `Fn::Base64`; diagnose via `/var/log/cloud-init-output.log`; procedural one-shot vs cfn-init desired-state), instance roles & instance profiles (instance role = IAM role trusting `ec2.amazonaws.com` so an app reaches other AWS services with **no stored access keys**; a role can't attach directly — an **instance profile** wrapping one role is what attaches; console auto-creates a same-name profile while CLI/CloudFormation create role + profile as separate objects with possibly different names; temporary credentials delivered via **IMDS** at `iam/security-credentials/<role-name>` and **auto-renewed by EC2 + STS**; instance profile credentials are **last** in the CLI provider chain so the CLI just works — but env vars / `~/.aws/credentials` **silently shadow** the role; mnemonic **RPM** = Role-Profile-Metadata), placement groups (influence physical placement on hosts; **Cluster** = same rack often same host, 10 Gbps single-stream vs 5 normal, locked to the AZ of the first launch, needs supported type + enhanced networking, little resilience, HPC; **Spread** = 1 instance per isolated rack with own power + network, hard cap 7 running instances per AZ **per group** (not account-wide; multiple groups for more, no cross-group spread guarantee), spans AZs, no Dedicated Instances/Hosts; **Partition** = max 7 partitions per AZ with no infra sharing between them, unlimited instances, pick-partition-or-EC2-decides, topology visibility for HDFS/HBase/Cassandra), enhanced networking (**SR-IOV** makes the host's physical NIC virtualization-aware so each instance gets its own logical card and the **host CPU leaves the packet path**; without it the host arbitrates one shared card in software = slow, high CPU, latency spikes, inconsistent bandwidth; delivers more bandwidth, higher **PPS**, and **consistent low latency**; default/free on most modern types via the **ENA**; the **prerequisite for cluster placement groups**), EBS-optimized instances (per-instance on/off flag giving **EBS traffic its own dedicated network lane** instead of sharing one stack with data networking; since **EBS is network-attached**, this is the instance-side half of the per-instance IOPS ceiling and what lets an instance actually receive high throughput/IOPS; default-on + free on most modern types, paid opt-in on some older ones)
- [ECS](services/ecs.md) — Managed container orchestration (AWS-proprietary); cluster/service/task/container hierarchy, task definitions vs container definitions, task role vs execution role, services for desired-count HA and load balancing, registries/ECR, EC2 launch type vs Fargate launch type, capacity providers, Fargate ENI/VPC networking, EC2-vs-Fargate choice heuristics, and ECS-vs-EKS positioning
- [ECR](services/ecr.md) — Managed container image registry ("Docker Hub for AWS"); registry/repository/image/tag hierarchy (tags unique per repo), one private registry per account per region (regional resource) plus a public registry, public vs private permission model (public = anyone pulls, push needs permissions; private = permissions for all), IAM-controlled access with repository (resource) policies for cross-account pulls, Basic vs Enhanced image scanning (Enhanced = Amazon Inspector, OS + software packages, layer-by-layer), observability via CloudWatch/CloudTrail/EventBridge, and cross-region + cross-account replication
- [EKS](services/eks.md) — AWS-managed [Kubernetes](concepts/kubernetes.md); same cloud-agnostic Kubernetes with AWS running the control plane + etcd (both multi-AZ), deployment modes (AWS / Outposts / EKS Anywhere / EKS Distro), cluster endpoint access (public/private/both), integrations (ECR/ELB/IAM/VPC), node options (self-managed EC2 / managed node groups / Fargate via Fargate profiles), capability-support caveats (Windows/GPU/Inferentia/Bottlerocket/Outposts/Local Zones), persistent storage providers (EBS/EFS/FSx), two-VPC architecture (control plane in AWS-managed VPC, EC2 workers in customer VPC, connected via injected ENIs or public endpoint), per-cluster control-plane fee, and ECS-vs-EKS decision framing
- [S3](services/s3.md) — Object storage; foundations (global platform on regional infrastructure, multi-AZ resilience with per-region blast radius, objects + buckets primitives, 0 B–5 TB object size, unlimited objects, 100 soft / 1,000 hard buckets per account, globally unique bucket names with DNS-style naming rules, flat namespace where "folders" are key prefixes, object vs file vs block storage decision against EFS / FSx / EBS), bucket policies, ACLs (legacy), Block Public Access, cross-account & anonymous access, pre-signed URLs (time-limited single-object access; IAM user vs role; permissions evaluated at use time), versioning + MFA Delete, Object Lock (WORM immutability for object versions; Compliance vs Governance retention; Legal Hold; bucket-level permanence — auto-enables versioning and cannot be disabled), object encryption (SSE-S3 / SSE-KMS / SSE-C / CSE) + S3 Bucket Keys, multipart upload + Transfer Acceleration, storage classes (Standard / IA / One Zone-IA / Glacier tiers / Intelligent-Tiering), lifecycle configuration (transitions + expiration; waterfall rules; 30-day Standard minimum; single-rule IA-to-Glacier gap), replication (CRR / SRR; same-account vs cross-account; RTC 15-min SLA; what's not replicated), server-side filtering (S3 Select / Glacier Select; SQL-like row/column filter pushed into the service; per-object only — Athena for multi-object), event notifications (Lambda / SQS / SNS destinations; Create/Delete/Restore/Replicate event types; destination resource policy must trust `s3.amazonaws.com`; EventBridge as the broader alternative), access logging (async best-effort request-level audit log; same-account same-region source → target bucket; Apache-style records; target bucket policy grants `logging.s3.amazonaws.com`; CloudTrail data events as the real-time / structured alternative), access points (scoped DNS doorways into one bucket; per-AP policy ≤ 20 KB; Internet or VPC origin immutable after creation; two-layer permissions rule with `s3:DataAccessPointAccount` delegation; not a replication destination), Multi-Region Access Points (single global endpoint over 2+ replicated buckets in different regions; latency-routed; active/active or active/passive failover; mesh CRR required; subject to async replication lag — mitigate with RTC)
- [CloudFormation](services/cloudformation.md) — Infrastructure as code; templates (YAML/JSON) create stacks; `${AWS::StackId}`/`${AWS::Region}` substitution; **cfn-init** desired-state bootstrapping (version-aware packages/files/services/commands in `AWS::CloudFormation::Init` metadata, invoked from user data, procedural-or-desired-state unlike user data's procedural-only); configSets of ordered config keys; **cfn-hup** re-runs cfn-init on stack-metadata changes (user data is one-shot); **CreationPolicy + cfn-signal** (`-e $?`) hold-point handshake with timeout = how CFN knows in-instance bootstrapping actually succeeded; diagnose via `/var/log/cfn-init-cmd.log`
- [Systems Manager (SSM)](services/ssm.md) — Ops-management suite (Parameter Store, Session Manager, Run Command, Patch Manager, …); **Parameter Store** documented in depth: config/secrets store and the correct alternative to EC2 user-data secrets; String/StringList/SecureString types; hierarchical tree names with per-parameter or per-tree IAM (retrieve by full name vs by branch with `get-parameters-by-path`); public AWS-published parameters (latest-AMI-ID for CloudFormation); regional + multi-AZ but no cross-Region replication; SecureString needs SSM **and** KMS permissions (role separation); symmetric KMS keys only; standard tier (4 KB, direct KMS encrypt, free, 10K/Region) vs advanced tier (8 KB, envelope encryption via Encryption SDK, parameter policies, billable, 100K/Region, no downgrade); permissions split (standard encrypt `kms:Encrypt`, advanced encrypt `kms:GenerateDataKey`, decrypt both `kms:Decrypt`); `PARAMETER_ARN` encryption context; Parameter Store vs Secrets Manager (rotation/native-DB → Secrets Manager)
- [Route 53](services/route53.md) — Authoritative DNS; hosted zones, Alias records, health checks, Resolver, and the full set of routing policies: **simple**, **weighted** (probability `weight ÷ total weight`, weights need not sum to 100, weight-0 unless all-0, health checks don't change the denominator), **latency** (one record per name per region tagged with an AWS region, lowest-estimated-latency-healthy from AWS's non-real-time latency database), **failover** (active/passive, two same-name records gated by a health check, out-of-band EC2-primary/S3-secondary maintenance pattern), **geolocation** (relevance by tagged state/country/continent/default with first-match specificity order — never the closest record, "no answer" if no match and no default), **geoproximity** (closest by physical distance via AWS region or lat/long, with `+`/`-` bias to grow/shrink a resource's service area), **multi-value** (up to 8 random healthy per-record-health-checked records, improves availability but is not a load balancer)
- [Organizations](services/organizations.md) — Multi-account management; OUs, consolidated billing, SCPs, cross-account role-switching
- [Control Tower](services/control-tower.md) — "Organizations with superpowers"; orchestrates Organizations + IAM Identity Center + CloudFormation + Config + CloudWatch/CloudTrail/SNS + Service Catalog into a well-architected multi-account setup; four parts (Landing Zone, Guardrails/Controls, Account Factory, Dashboard); home region always available; default OUs (Foundational/Security holding Audit + Log Archive accounts, Custom/Sandbox); Log Archive = isolated read-only Config+CloudTrail log store, Audit = SNS/CloudWatch governance visibility + third-party audit tooling; guardrails on two axes (enforcement: mandatory/strongly-recommended/elective; type: preventative=SCP stops, detective=Config flags, optional proactive=CFN hooks); Account Factory self-service provisioning with cookie-cutter account+network baselines (non-overlapping VPC IPs)
- [CloudWatch](services/cloudwatch.md) — Monitoring & observability; CloudWatch Logs hierarchy (log group → stream → event), metric filters, alarms; **CloudWatch Agent** (the only way to get in-guest memory/disk-used/per-process metrics and OS/app logs off an EC2 instance — standard CloudWatch sees the instance only from outside; needs a JSON config + an instance role with `CloudWatchAgentServerPolicy`; "group by file, stream by instance" log mapping; OS metrics land in the `CWAgent` namespace; config stored once in SSM Parameter Store for fleet reuse; reads a log only if its run-as user `cwagent` has file read permission — IAM governs send, file perms govern read)
- [CloudTrail](services/cloudtrail.md) — Audit & governance; records API/account activity as events; free 90-day Event History (management events only) vs trails for retention/delivery; event types (management default / data opt-in + cost / Insight anomaly detection); single-region vs all-regions trails; global service events (IAM, STS, CloudFront, Route 53) deliver to us-east-1; S3 (compressed JSON, indefinite, optional SSE-KMS) + optional CloudWatch Logs delivery; organizational trail from the management account; log file integrity validation (SHA-256 + signed digests); not real-time (~15 min log delivery — use EventBridge on management events for fast reactions)
- [KMS](services/kms.md) — Key Management Service; symmetric/asymmetric keys, 4 KB direct limit, envelope encryption with DEKs, key ownership tiers (AWS Owned / AWS Managed / Customer Managed), key policies + IAM + grants

## Patterns

- [Cost Optimization](patterns/cost-optimization.md) — Savings Plans (Compute / EC2 Instance), Reserved Instances, Spot; decision tree; pooling via Organizations
- [Boot Time to Service Time](patterns/boot-time-optimization.md) — AMI baking vs bootstrapping vs combined; boot-time-to-service-time = provisioning time + post-launch config time; bake the slow/stable part and bootstrap the fast-changing part (the **optimal** combined pattern); exam pattern "minimize boot time while keeping flexibility" → combine both; matters for Auto Scaling responsiveness
- [Scaling — Horizontal vs Vertical](patterns/scaling.md) — bigger box vs more boxes; vertical = simple, monolith-friendly, but stop/start disruption and hard upper cap; horizontal = no upper limit, no disruption, finer granularity, cheaper commodity instances — but requires a load balancer (ELB / ALB / NLB) and stateless application design with sessions stored off-host (ElastiCache / DynamoDB / RDS); sticky sessions are a migration aid, not the proper fix; foundation for ELB + Auto Scaling Groups across multi-AZ HA
- [EC2 Purchase Options](patterns/ec2-purchase-options.md) — EC2-focused deep dive on all 7 options: On-Demand Instances (default, no capacity priority), Spot Instances (~90% off, terminated when current Spot price > your max — max sets tolerance not rate), Standard Reserved Instances (~72% max; 3-yr All-Upfront = biggest discount; Zonal Reserved Instance includes capacity, Regional doesn't), Convertible Reserved Instances (~54% max; exchangeable for equal/greater value when family/OS/tenancy changes — Standard and Convertible can each be Regional or Zonal), Scheduled Reserved Instances (recurring time-window — **retired 2024-09-03**, use On-Demand Capacity Reservations), Capacity Reservations (discount and capacity are separate axes — Regional Reserved Instance = discount only, On-Demand Capacity Reservation = capacity only billed-if-idle, Regional Reserved Instance + On-Demand Capacity Reservation = both; Zonal Reserved Instance's discount does NOT stack with a separate Capacity Reservation), Savings Plans (Compute Savings Plans ~66% across EC2/Fargate/Lambda, EC2 Instance Savings Plans ~72% family+Region-locked), Dedicated Hosts (per-host billing, BYOL per-socket licensing, Host Affinity), Dedicated Instances (no co-tenant hardware, host opaque, per-Region hourly fee); capacity priority under shortage: **Reserved Instances → On-Demand Instances → Spot Instances**
